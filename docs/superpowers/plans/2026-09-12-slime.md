# 苔光森林 Implementation Plan

> Execute inline with superpowers:executing-plans. User approved design and implementation on 2026-09-12.

**Goal:** Build a playable one-level browser adventure centered on a deforming, splitting PBF slime.
**Architecture:** A renderer-independent fixed-step particle solver feeds level rules and a Phaser scene. Procedural environment artwork and continuous particle contours share world geometry. DOM HUD owns instructions and pause controls.
**Tech Stack:** TypeScript, Vite, Phaser, Vitest, Playwright.
**Spec:** ../specs/2026-09-12-slime-design.md

## Global constraints
- One forest level, desktop keyboard first, no backend.
- Real PBF density constraints; cohesion/viscosity supplement the solver.
- Split conserves mass, merge requires proximity and unobstructed contact.
- Physics at 1/120 s, rendering independent; pause and blur clear held keys.
- Programmatic environment art; no image generation API used.

## Execution record

Implemented all four deliverables. The actual solver uses 197 particles after performance tuning. Continuous contours use marching squares and Canvas gradients, with Phaser static-layer caching; hardware WebGL is preferred and software GPU environments automatically fall back to Canvas. Water uses buoyancy, drag and reactive waves rather than an independent particle phase. These implementation limits are documented in README.md.

Validation artifacts: output/browser-results.json, output/route-results.json and numbered screenshots. Added regressions for inactive-body drift, per-body jump grace, variable-height jump and keyboard activation of pause controls.
