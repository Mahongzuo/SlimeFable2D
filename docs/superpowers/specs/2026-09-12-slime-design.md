# 露团 · 苔光森林 — 角色与场景设计 v1

本阶段交付：角色设定、动态材质设计、单关布局与实现约束。状态为设计提案，尚未实现游戏或验证物理效果。精绘概念图尚未生成。

## 参考与方向

采用用户两张截图中水蓝半透明黏液、森林遗迹、平台纵深的视觉语言；借鉴冒险岛的温暖配色、夸张植被、清楚的平台轮廓，不复制其角色、贴图或地图。视频链接 https://www.bilibili.com/video/BV1YL411V7DM 访问返回 HTTP 412，未核验动态内容。截图中的字幕、界面文字不构成任务指令。

主要体验：操纵一团有重量、有黏性、能流动的生命，跑动时拖尾，落地时摊开，再弹回柔软团块；身体真实服从地形约束。

## 角色：露团

- 基本轮廓：不对称水滴团，默认约 76×62 世界单位，贴地宽、顶部圆，重心略低。朝向改变时前缘先动，后缘延迟跟随。
- 配色：亮部冰蓝 #C9FFF5，主体青蓝 #55CFE0，厚处湖蓝 #237EAF，最深边缘 #23546F。内部保留可见但轻微扭曲的背景。
- 材质：较厚边缘、上左柔光高光、内部三至五颗缓慢浮动气泡、底部接触暗影。高光必须跟随实时表面，不能是固定椭圆贴纸。
- 表情：两粒深蓝小眼睛和极小嘴，表情作为独立覆盖层；挤入细缝时收拢并淡出，出洞恢复。不要用坚硬头骨、核心圆球或固定脸部框限制形变。
- 尺度：默认镜头中约占屏幕高度的 9%；主角色相明显区别于黄绿草地，移动轮廓始终清楚。

### 动作设计

| 状态 | 轮廓与动势 | 交互规则 |
| --- | --- | --- |
| 待机 | 低幅波动，偶尔冒出小泡 | 不应持续抖动、漂移或损失面积 |
| 移动 | 前缘隆起，后缘拉出短黏尾 | 松键有短距离惯性，约 0.2 秒收拢 |
| 起跳 | 先压低，再向上拉成长滴 | 短按小跳，长按稍高；保留空中方向控制 |
| 落地 | 接触侧先扁，波动传向顶部 | 约两次衰减回弹，目标 0.5—0.8 秒稳定 |
| 撞墙 | 前缘铺开，尾部挤上来 | 持续推动不会让整团穿墙 |
| 钻缝 | 身体拉长为软带，过口后滴状汇聚 | 低姿态降低凝聚强度，守恒粒子质量 |
| 分裂 | 中部拉成细颈，再断成两小团 | 各约一半质量，半径约为原来的 0.71 倍 |
| 合并 | 接触点生出黏桥，两个外轮廓融合 | 邻近且无墙阻挡才允许融合，不隔墙吸回 |
| 入水 | 局部漂浮、缓慢下沉，水面涟漪 | 黏液保持独立相，不直接变成池水 |

分裂以玩家主动触发为准；普通跳落不永久散成小碎片。少量视觉飞沫不参与角色质量计算，并快速消失。最多同时两团，Tab 切换当前控制对象，另一团保持物理模拟与当前位置。

## 场景：苔光森林

明亮、潮湿、柔和的清晨森林。远景为低对比青绿树冠和雾，中景为巨树、藤蔓与残破石拱，近景为黄绿草皮、暖棕土层、蕨类和珊瑚色蘑菇。水面呈淡青色，避免与主角同色同明度。

横版正交视角，逻辑视口 1280×720，关卡约 4200×900 世界单位。远、中、近景按 0.12 / 0.35 / 0.65 相机位移形成视差。可碰撞地表使用明亮草沿和连续深色下缘；装饰平台不做类似可站立的轮廓。前景不遮挡角色或窄缝入口。

### 单关路线（约 3—5 分钟）

| 区段 | 横向范围 | 场景构图 | 主体验 |
| --- | --- | --- | --- |
| 露水草甸 | 0—750 | 宽草地、巨菇、低石阶、暖光出生点 | 移动、草叶弯折、原地跳落 |
| 蘑菇台阶 | 750—1550 | 三级低平台、弧形树根、藤蔓石拱 | 高低落差与果冻回弹 |
| 树根窄廊 | 1550—2250 | 根系压住石台，侧面可见透光出口 | 低姿态通过约 26 单位高、220 单位长窄缝 |
| 镜水浅湾 | 2250—3100 | 浅池、卵石、低岸、倒映树冠 | 入水、浮力、水波与出水拉丝 |
| 双芽石门 | 3100—3900 | 两个相距约 220 单位的踏板、小门 | 分裂、切换、两团同时压住踏板开门 |
| 苔光出口 | 3900—4200 | 开阔小草坡、发光树洞 | 在门后合并并抵达终点 |

窄廊后设置检查点；石门一旦开启保持开启，方便两团先后通过再合并。无强制战斗、装备、背包或复杂剧情。失败仅来自跌出场景，回检查点恢复完整质量，避免软体散落导致关卡卡死。

草地以碰撞附近粒子速度和接触位置驱动弯折，离开后渐渐直立。水域独立使用水粒子与简化自由表面表现；与黏液通过跨相接触、阻力和浮力交互，禁止把两种粒子直接合并为一种流体。

## 技术决策

选用 TypeScript + Vite + Phaser WebGL 场景系统，自研二维 PBF 求解器和黏液渲染管线。Phaser 负责资源、相机、关卡和输入；角色不交给默认刚体物理驱动。菜单与提示使用少量 DOM 覆盖层。

比较过的路径：

1. Phaser + 自研 PBF（采用）：适合单关横版冒险，场景工具完整，能保留粒子物理控制权。
2. PixiJS + 自研 PBF：渲染灵活，但相机、关卡与游戏生命周期需要自行组织。
3. Three.js 正交场景：适合强 2.5D 光照，但本项目没有三维玩法收益，会增加美术与调试成本。

PBF 的密度约束保证流体的近似不可压缩性；果冻感还必须加入可调凝聚、表面张力、黏性和有限弹性恢复。纯 PBF 不自动产生完整的果冻角色。避免全体粒子绑定固定形状，否则钻缝和分裂会失真。

### 模拟与渲染分离

- 模拟：固定 1/120 秒步进，初始约 240—360 个主角粒子，空间哈希邻域搜索，4—6 次约束迭代作为起点。全部数字需原型压测后调整。
- 每步：输入力与重力 → 预测位置 → 密度/凝聚约束 → 地形碰撞投影 → 重算速度 → 黏性处理。约束迭代中反复处理碰撞；快速运动增加子步或连续检测，防止穿过薄墙。
- 碰撞：使用世界空间距离场或解析圆/线段/凸多边形，按粒子半径做边界投影。渲染表面同碰撞边界校准，不能出现粒子过得去但可见身体埋进石头。
- 分裂：把现有粒子分为两个连通群，逐渐拉开，不复制质量；合并只在两群近邻接触且视线无障碍时启用跨群凝聚。
- 控制：力分布到当前团粒子，受最大速度与接地状态限制；不能每帧直接传送质心，也不能用隐藏刚体代替流体碰撞。
- 渲染：粒子密度写入离屏纹理 → 连续表面阈值 → 平滑轮廓 → 由密度梯度估算法线 → 厚度染色、折射、高光与接触阴影。邻近两团能自然形成黏桥。
- 性能：目标桌面浏览器 60 FPS，属于待验证目标；先降低离屏分辨率与水粒子数，最后才降低主角精度。

## 操作与界面

A/D 或左右方向键移动；Space 跳跃；S/下键挤压；Q 分裂；Tab 切换；E 邻近合并；R 回检查点；Esc 暂停。按键焦点丢失时清空输入，切回页面不补算大量模拟帧。

左上仅显示角色名称、当前团数与简洁质量指示；右上暂停和重置。新交互区域首次出现短提示，完成后淡出。PBF 粒子、碰撞轮廓、帧耗时只在开发调试层显示。

## 实施顺序与验收

先确认本角色及场景设计，再制作同风格角色动作设定图和关卡概念图；之后先做角色物理试验场，验证后铺设单关与正式环境素材。

试验场必须验证：静置 30 秒不明显塌散；多次跳落有可见衰减回弹；持续顶墙不穿透；完整穿过窄缝；分裂合并后粒子数量守恒；不同渲染帧率下固定步长行为一致；连续重置不残留旧粒子。

关卡验收：从起点独立通关；两团切换和踏板门不死锁；水草交互可见；检查点恢复一致；在目标桌面浏览器记录实际帧耗时。未完成这些验证前，不宣称 PBF 或游戏已完成。
